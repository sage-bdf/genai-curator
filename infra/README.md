# Curator Workflows Infrastructure

This folder contains the AWS CDK code for deploying the Curator Workflows infrastructure.

## Architecture

The infrastructure consists of:

1. **API Gateway with API Key authentication**
   - 4 endpoints:
     - GET /task_status
     - POST /fix_metadata (returns pre-signed S3 URL)
     - POST /extract_metadata (returns pre-signed S3 URL)
     - POST /transform_metadata (returns pre-signed S3 URL)

2. **Lambda Functions**
   - API endpoint handlers that generate pre-signed URLs for file uploads
   - Step function task handlers for processing documents, fixing values, and translating tables
   - Task status Lambda queries Step Functions API directly for job status

3. **S3 Bucket**
   - Storage for input files (documents, tables) and output files (processed metadata)
   - Files are uploaded via pre-signed URLs generated by Lambda functions

5. **Step Functions**
   - Extract Metadata: Extracts metadata from research papers
   - Fix Values: Fixes unapproved values in metadata tables
   - Table Translation: Translates metadata from one schema to another
   - Maintains execution state and status that can be queried via API

## Deployment Guide

### Prerequisites

1. AWS CLI installed and configured with appropriate credentials
2. Python 3.10 or higher
3. Node.js 14 or higher (required for AWS CDK)
4. AWS CDK installed globally: `npm install -g aws-cdk`

### Setup

1. Clone the repository and navigate to the infra directory:

```bash
cd infra
```

2. Create and activate a virtual environment:

```bash
python3 -m venv .venv
source .venv/bin/activate  # On Windows: .venv\Scripts\activate
```

3. Install dependencies:

```bash
make install
```

4. Bootstrap AWS CDK (if not already done):

```bash
cdk bootstrap
```

### Deployment

To deploy all stacks:

```bash
make deploy
```

This will deploy the following stacks:

- GenAICuratorStorageStack: S3 bucket
- GenAICuratorStepFunctionsStack: Step functions and related Lambda functions
- GenAICuratorApiStack: API Gateway and API endpoint Lambda functions

### Local Development

For local development and testing, you can use the provided script:

```bash
./scripts/local_dev.py
```

This script simulates the API Gateway and Lambda functions locally, allowing you to test the application without deploying to AWS.

## Testing

After deployment, you can test the API using the following commands:

1. Get the API URL and API Key from the AWS Console (API Gateway service)

2. Test the extract_metadata endpoint:

```bash
curl -X POST \
  https://<api-id>.execute-api.<region>.amazonaws.com/prod/extract_metadata \
  -H 'Content-Type: application/json' \
  -H 'x-api-key: <api-key>' \
  -d '{"schemaName": "MC2", "fileType": "application/pdf"}'
```

3. Test the fix_metadata endpoint:

```bash
curl -X POST \
  https://<api-id>.execute-api.<region>.amazonaws.com/prod/fix_metadata \
  -H 'Content-Type: application/json' \
  -H 'x-api-key: <api-key>' \
  -d '{"schemaName": "MC2", "fileType": "text/csv"}'
```

4. Test the transform_metadata endpoint:

```bash
curl -X POST \
  https://<api-id>.execute-api.<region>.amazonaws.com/prod/transform_metadata \
  -H 'Content-Type: application/json' \
  -H 'x-api-key: <api-key>' \
  -d '{"schemaName": "MC2", "fileType": "text/csv"}'
```

5. Test the task_status endpoint:

```bash
curl -X GET \
  'https://<api-id>.execute-api.<region>.amazonaws.com/prod/task_status?jobId=<job-id>&workflow=<workflow>' \
  -H 'x-api-key: <api-key>'
```

## Cleanup

To destroy all stacks:

```bash
make destroy
```

## Troubleshooting

1. **Permission Issues**: Ensure your AWS credentials have sufficient permissions to create all the required resources.

2. **Deployment Failures**: Check the CloudFormation console for detailed error messages.

3. **Lambda Function Errors**: Check CloudWatch Logs for Lambda function logs.

4. **API Gateway Issues**: Ensure the API Key is correctly set in the request header.


6. **Local Development**: If the local development server is not working, ensure you have the correct AWS credentials and permissions set up locally.
